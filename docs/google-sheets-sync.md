# Синхронизация с Google Таблицами

Ветка: `feature/voice-reminders`. Статус: готово, входит в 3.4.0.

## Задача

Пользователь вводит свою Google Таблицу — и все записи Нова (напоминания, заметки, задачи,
покупки, траты, сценарии, память) уезжают туда. Обратно тоже: после переустановки приложения
достаточно ввести те же значения, и всё вернётся из таблицы.

## Решение: Apps Script как посредник

Прямого доступа к Google Sheets API нет и быть не может: он требует OAuth-клиента, а значит —
секрета в открытом репозитории и проверки приложения в Google. Поэтому посредником работает
веб-приложение Apps Script, которое пользователь разворачивает у себя:

1. Создаёт пустую таблицу, копирует ссылку.
2. Расширения → Apps Script → вставляет код Нова (кнопка «Открыть код скрипта» в приложении).
3. Разворачивает как веб-приложение: «Запуск от имени» — я, «Доступ» — все.
4. Придумывает код доступа, вставляет его и в приложение, и в скрипт.

Итого три значения в приложении: ссылка/ID таблицы, адрес веб-приложения, код доступа.
Код доступа хранится в Android Keystore, а не в обычных настройках.

Почему так: данные остаются в аккаунте пользователя, у Нова нет ни своего сервера, ни доступа
к чужому Google-аккаунту, а код скрипта виден и проверяем.

## Формат листа

Лист `Нова`, колонки:

| table | id | updated_at | deleted | payload |
|---|---|---|---|---|
| reminders | 6f2c… | 1764249600000 | false | `{"id":…,"text":"выпить таблетку",…}` |

- `table` — имя таблицы в терминах синхронизации (`reminders`, `notes`, `tasks`, `shopping_items`,
  `expenses`, `routines`, `memories`, `conversation_messages`).
- `updated_at` — метка изменения в миллисекундах; по ней решается, чья версия новее.
- `deleted` — надгробие: удаление на телефоне должно доехать до таблицы и до других устройств.
- `payload` — сама запись в серверном формате (тот же, что у Supabase), JSON-строкой.

Слияние — last-write-wins по `updated_at`. При равных метках побеждает локальная версия.
Записи длиннее 45 000 символов в ячейку не влезают (лимит Google — 50 000): такие пропускаются
и считаются в отчёте, чтобы не сломать запись листа целиком.

## Что уже сделано

### core (без Android, покрыто тестами)

- `core/src/main/kotlin/ai/nova/core/sync/SheetsSync.kt`
  - `SheetsRow` — строка листа.
  - `SheetsSync.spreadsheetId()` — ID из ссылки `docs.google.com/spreadsheets/d/…/edit` или из
    вставленного руками ID; мусор отклоняется.
  - `SheetsSync.merge()` — слияние локального и табличного наборов, надгробия участвуют,
    слишком длинные payload отбрасываются со счётчиком, порядок стабильный.
  - `SheetsSync.MAX_CELL = 45_000`.
- `core/src/test/kotlin/ai/nova/core/sync/SheetsSyncTest.kt` — 9 тестов, все зелёные
  (`./gradlew -Pnova.skipAndroid=true :core:test` → BUILD SUCCESSFUL).

### app

- Настройки (`SettingsRepository.kt`): `sheetsId`, `sheetsWebAppUrl`, `sheetsAutoSync`,
  `sheetsLastSyncAt` + сеттеры + ключи DataStore.
- Секрет (`KeystoreSecretStore.kt`): `SHEETS_TOKEN`.
- `app/.../sync/SheetsSyncEngine.kt` — HTTP-клиент к веб-приложению: собирает строки из всех
  синхронизируемых таблиц, шлёт `action=sync`, применяет ответ (только то, что новее локального),
  пишет `sheetsLastSyncAt`. Есть `test()` — проверка связи без отправки записей.
  Ошибки не вылетают наружу, а возвращаются в `Report` — Worker не падает.
  Проходы не пересекаются (Mutex), а при применении ответа проверяется, что локальную запись
  не изменили, пока шёл запрос — правка пользователя не затирается.
- `app/.../sync/SheetsScript.kt` — текст Apps Script с подстановкой кода доступа; кавычки,
  обратные слэши и переводы строк в коде доступа экранируются, чтобы скрипт не ломался.
- `app/.../sync/SheetsWorker.kt` — `SheetsWorker` + `SheetsScheduler` (WorkManager: раз в 15 минут
  и «скоро» после локальных изменений, только при сети; без настроенных значений не повторяет
  попытки впустую).
- `AppContainer.kt` — `sheetsSync`, `sheetsScheduler`, планирование при старте и подписка на
  изменения базы.
- `app/.../ui/screens/SheetsScreen.kt` — экран «Google Таблицы»: три поля, «Сохранить и
  синхронизировать», «Синхронизировать», «Проверить связь», переключатель автосинхронизации,
  инструкция из 4 шагов, диалог с кодом скрипта и копированием в буфер, дата последней
  синхронизации, пояснение про приватность.
- `SettingsScreen.kt` — страница `SHEETS` («Google Таблицы») в списке настроек.

## Что осталось

1. **Проверить на устройстве** (устройства в этой среде нет):
   - создать таблицу, развернуть скрипт, ввести три значения;
   - «Проверить связь» → «Связь есть»;
   - создать напоминание → «Синхронизировать» → строка появилась в листе;
   - удалить приложение, поставить заново, ввести те же значения → записи вернулись;
   - включить автосинхронизацию → правка уезжает сама.
2. **Собрать релизный APK** — `:app:assembleDebug` и `:core:test` проходят. Подпись для
   релиза лежит только в секретах GitHub Actions, локально её нет: релиз собирается
   workflow «Release APK» из тега или вручную.
3. **Коммит и пуш** в `feature/voice-reminders` — сделано (`ee2bd56`).

Версия уже поднята: `APP_VERSION` = 3.4.0, в `Changelog.kt` добавлены записи 3.3.0 (напоминания
вслух) и 3.4.0 (Google Таблицы).

## Ограничения, о которых надо помнить

- Синхронизация идёт целыми таблицами: на каждое изменение уезжает полный набор строк. Для
  тысяч записей это тяжело — при необходимости добавить инкрементальную отправку по курсору
  (в таблицу можно писать только изменённое после `sheetsLastSyncAt`).
- Веб-приложение Apps Script имеет квоту на выполнение (около 6 минут на запуск, суточные лимиты
  на аккаунт). Для личного использования этого с запасом, для больших объёмов — нет.
- Скрипт перезаписывает лист целиком (`clearContents` + `setValues`): формулы и оформление в
  листе «Нова» не сохранятся, поэтому лист должен быть служебным.
- История чата попадает в таблицу только при включённой синхронизации чата (`syncChat`), как и
  в Supabase.
- Ключи AI, пароль базы и сессия аккаунта в таблицу не попадают никогда.
