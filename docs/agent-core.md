# Ядро агента (Agent Core)

Ядро агента добавлено в 2.17.0. Оно не заменяет прежний конвейер понимания фразы, а надстраивается над ним:
существующие навыки продолжают работать как раньше, а ядро добавляет составные запросы, контекст между
репликами и постоянное состояние задач.

```
фраза ──▶ AssistantEngine.process
             ├─ 0.3  agentTurn      ← план из нескольких намерений (Agent Core)
             ├─ 0.4  cookingTurn    ← рецепт, покупки, пошаговая готовка
             ├─ …    навыки, локальный разбор, AI, офлайн-модель
```

## Состав

| Файл | Что делает |
|---|---|
| `core/.../agent/SkillRegistry.kt` | Манифесты навыков: id, описание, фразы-триггеры, приватность, признак «меняет данные», сущность, которую навык находит. |
| `core/.../agent/IntentRecognizer.kt` | Делит фразу на намерения и строит `AgentPlan`. |
| `core/.../agent/ToolExecutor.kt` | `AgentTool` + `ToolRegistry` + `ToolExecutor`: таймаут, отмена, повторы для чтения, защита от дублей для изменений, лог. |
| `core/.../agent/ContextManager.kt` | Активная задача, шаги, последняя сущность. Память + постоянное хранилище. |
| `core/.../agent/AgentStore.kt` | SQLDelight: `agent_task`, `agent_step`, `agent_context`. |
| `core/.../agent/AgentCore.kt` | Точка сборки: реестр + инструменты + контекст + разбор фразы. |

## Как принимается решение о составной фразе

1. Фраза делится только по явным связкам: `, потом`, `затем`, `после этого`, `и ещё`, `;`
   — или по «и», если справа начинается явная команда (`запиши`, `добавь`, `найди`, `включи`…)
   и обе части не короче трёх слов.
2. Каждая часть должна опознаваться реестром навыков.
3. Хотя бы одно намерение должно менять данные или находить сущность — иначе фраза обрабатывается как раньше
   («какая погода и что нового» не становится задачей).
4. Фразы, задающие сценарий (`когда я говорю…`, `если…`), не делятся никогда.
5. Ссылки «его/её/это» разрешаются, только если сущность уже есть или её найдёт предыдущий шаг этой же фразы.
   Иначе фраза уходит в обычный путь: пустых заметок и выдуманных покупок не появляется.

Примеры:

- `найди рецепт борща и запиши его в заметки` → рецепт + заметка «Рецепт Борщ».
- `найди рецепт борща и добавь его в покупки` → рецепт + ингредиенты в списке покупок.
- `купила молоко и хлеб` → одна команда (существующая ветка), не составная.

## Состояние задач

```sql
agent_task(id, kind, title, state, step_index, total_steps, payload, created_at, updated_at)
agent_step(id, task_id, step_index, skill, input, output, state, error, duration_ms, created_at)
agent_context(key, content, updated_at)      -- last_entity и другие ключи
```

`state` задачи: `NOT_STARTED`, `IN_PROGRESS`, `WAITING_FOR_USER`, `PAUSED`, `COMPLETED`, `CANCELLED`.
Задачи старше суток и сущности старше 30 минут вычищаются при старте приложения (`AgentCore.vacuum()`).

## Контракт инструмента

```kotlin
interface AgentTool {
    val id: String
    val title: String
    val mutating: Boolean get() = false
    suspend fun run(input: String): ToolResult
}
```

- `ToolExecutor` ловит любые исключения и возвращает `ToolResult.fail(...)` — инструмент не может уронить приложение.
- Таймаут по умолчанию — 20 секунд; по истечении возвращается понятная ошибка.
- Повторы (2 попытки) — только для читающих вызовов; изменяющие выполняются один раз.
- Одинаковый изменяющий вызов в течение минуты не выполняется второй раз (идемпотентность).

## Как добавить навык

1. Добавьте манифест в `SkillRegistry.defaults()`: `id`, `title`, `description`, `triggers` (регулярные выражения
   по нормализованному тексту — нижний регистр, «ё» → «е»), примеры для справки, `privacy`, `mutates`.
2. Если навык находит то, на что можно сослаться «его/её», укажите `producesEntity` (`AgentEntity.RECIPE/ARTICLE/SONG`)
   и верните сущность в `AssistantReply.entity`.
3. Обработчик оставьте в прежнем месте (`Skills`, `LocalCommandParser`, `AssistantEngine`) — ядро вызывает его
   через существующий конвейер.
4. Добавьте тест в `core/src/test/kotlin/ai/nova/core/agent/`.

## Тесты

- `AgentCoreTest` — разбор фраз, реестр, таймауты и идемпотентность инструментов, восстановление задачи после
  «перезапуска», сквозные сценарии рецепт → заметка и рецепт → покупки.
- `AgentMigrationTest` — миграция `3.sqm` на базе версии 3: таблицы появляются, старые записи целы.

## Кухня (2.18.0)

Рецепт — это структура, а не строка:

| Слой | Что делает |
| --- | --- |
| `RecipeIngredient` | `name`, `quantity`, `unit`, `note`; разбирает «рис — 500 г», «500 г мяса», «соль по вкусу»; пересчитывает и склоняет единицы («2 головки», «5 головок») |
| `KitchenRecipe` | `ingredients`, `steps`, `servings` (по умолчанию 4), `source`; `scaled(n)` пересчитывает количества |
| `CookingStore` | таблицы `recipe` и `cooking_session`: рецепт в JSON — с количествами, сессия — шаг и состояние |
| `SqlShoppingRepository.add(list, texts, source)` | разбирает количества, объединяет дубли: повторное «добавь в покупки» складывает граммы, а не создаёт вторую строку |

Сценарий:

1. «Как приготовить плов» → карточка с количествами, «На 4 порции», предложение покупок и шагов.
2. «На 6 порций» → `KitchenRecipe.scaled(6)`: 500 г риса → 750 г, карточка и покупки пересчитаны.
3. «Добавь в покупки» → пункты с количеством и источником (`source = «плов»`).
4. «Да» / «помоги приготовить плов» → пошаговый режим; каждый шаг пишется в `cooking_session`.
5. Перезапуск приложения → «продолжим готовить» поднимает рецепт и шаг из базы (`activeSession`, TTL 6 часов).

Готовка в памяти движка по-прежнему забывается через час молчания, но сессия в базе живёт дольше —
именно она отвечает за «на чём мы остановились» после перезапуска. Отменённая («хватит готовить») и
завершённая готовка не восстанавливаются.

## Ограничения

- Составная фраза делится максимум на три части.
- Понимание внутри частей — прежнее (правила, а не языковая модель), поэтому незнакомая формулировка
  может не опознаться; такие фразы остаются на обработке обычным путём.
- Сущность живёт 30 минут; после этого «запиши его в заметки» снова попросит уточнения.
