# Ключ подписи APK

Установленная Нова обновляется поверх только APK, подписанным тем же ключом. Поэтому ключ — самое ценное в репозитории.

## Как проверить, что установлена настоящая Нова

Исходники открыты: любой может собрать похожее приложение с изменённым кодом — например, с правом «Доступ к уведомлениям»
читать коды из SMS и пушей банков. Android не даст такой сборке встать *поверх* настоящей Нова (подписи разные), но на чистый
телефон её можно поставить под тем же именем. Единственная надёжная проверка — отпечаток ключа подписи:

1. В приложении: **Настройки → О приложении → Подпись приложения** (кнопка «Копировать»).
2. С компьютера: `apksigner verify --print-certs nova-<версия>-release.apk` или
   `keytool -printcert -jarfile nova-<версия>-release.apk` — строка `SHA256`.
3. Сверьте с опубликованным отпечатком ниже. Не совпадает — это не официальная сборка: удалите её.

**Отпечаток официального ключа (SHA-256):** `8A:5A:13:93:E8:70:EF:6E:F1:CD:FE:CE:52:3D:E1:37:C7:50:0F:5B:8C:DB:6A:F8:E9:81:6F:0D:C8:8E:87:27`

Ключ: RSA 4096, `CN=Nova Assistant, O=Nova`, alias `nova`, срок до 2054 года.
Релизы **до 3.1.0 включительно** подписаны другим, отладочным ключом (`CN=Android Debug`) — их отпечаток `C5:A3:E7:0E:…:82:22` официальным **не является** (см. «Перевыпуск ключа»).

Отпечаток публикуется здесь и в описании каждого релиза на GitHub. Если ключ перевыпускается (см. ниже), эта строка меняется,
и всем придётся один раз переустановить Нова — иного способа сменить ключ в Android нет.

Скачивайте APK только со страницы **Releases этого репозитория**. Автообновление внутри приложения берёт файл оттуда же и перед
установкой само сверяет имя пакета, подпись и версию ([UpdateManager.kt](../app/src/main/java/ai/nova/app/update/UpdateManager.kt)).

## Где он лежит сейчас
Рабочий ключ — в **секретах репозитория**: `NOVA_KEYSTORE_BASE64` (или старое имя `LOLI_KEYSTORE_BASE64`),
`NOVA_KEYSTORE_PASSWORD`, `NOVA_KEY_ALIAS` (`nova`), `NOVA_KEY_PASSWORD`. Секреты главнее кэша.

Кэш **не нужен**, пока есть секреты. Если секретов нет, `scripts/signing-key.sh` создаёт ключ и кладёт его в кэш
Actions (`nova-signing-key-v2`); кэш стирается через 7 дней без обращений, поэтому `keep-signing-key.yml` раз в неделю
к нему обращается. Проверки на pull request и на ветках ключа **не получают** и подписываются временным debug-ключом.

Подпись проверяется автоматически, дважды:

* `scripts/signing-key.sh` отказывается работать с отладочным ключом (`CN=Android Debug`) — его пароль «android» знают все;
* `scripts/verify-signing.sh` сверяет сертификат собранного APK с отпечатком из этого файла и **валит релиз** при расхождении.

Релиз собирается с `-Pnova.requireSigning=true`: без ключа сборка падает, а не подписывается debug-ключом молча
(именно так до 3.1.1 в релизы попадал отладочный ключ). Создать новый ключ можно только осознанно: запуск
`Release APK` с `new_key=true` (все установки придётся один раз удалить и поставить заново).

## Перевыпуск ключа (выполнен в 3.1.1)
Причина: сборки по 3.1.0 включительно подписывались отладочным ключом Android — в секрете лежал `debug.keystore`.
Такой ключ есть у любого разработчика, поэтому чужой APK с тем же `applicationId` и «правильной» подписью Android
поставил бы поверх Нова и получил доступ к уведомлениям, банковским пушам и данным приложения.

Как перевыпустить ключ (нужно и при будущей смене):

1. Создайте ключ у себя на компьютере:
   `keytool -genkeypair -keystore nova-release.jks -storetype PKCS12 -alias nova -keyalg RSA -keysize 4096 -validity 10000`
2. Закодируйте: `base64 -w0 nova-release.jks` (macOS: `base64 -i nova-release.jks`).
3. Settings → Secrets and variables → Actions → New repository secret:
   `NOVA_KEYSTORE_BASE64` (вывод шага 2), `NOVA_KEYSTORE_PASSWORD`, `NOVA_KEY_ALIAS` (`nova`), `NOVA_KEY_PASSWORD`.
   Старое имя `LOLI_KEYSTORE_BASE64` поддерживается, но лучше его удалить, чтобы не осталось двух источников правды.
4. Впишите новый отпечаток в этот файл — `verify-signing.sh` сверяет APK именно с ним.
5. Перезапустите `Release APK`. Кэш ключа сменил имя на `nova-signing-key-v2`: старый кэш с отладочным ключом больше не читается.
6. Храните `nova-release.jks` и пароли отдельно от репозитория (менеджер паролей, офлайн-копия).
   Потеряете — обновления перестанут ставиться, придётся перевыпускать ключ и переустанавливать приложение.

После смены ключа установленная Нова **не обновится поверх**: версии до 3.1.0 подписаны старым ключом. Один раз нужно
удалить приложение и поставить APK из Releases заново (данные при этом теряются — их можно сохранить резервной копией
в настройках).

## Если ключ мог утечь
Утечкой считается запуск чужого workflow с доступом к кэшу до версии 2.3.0, а также публикация релиза с отладочным
ключом (до 3.1.0): такой ключ подделать может кто угодно. Признаков утечки Actions не оставляет. Перевыпуск ключа
(шаги выше) закрывает риск ценой одной переустановки.
